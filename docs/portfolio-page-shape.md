# Архитектура страницы портфолио

Статус: подтверждённый дизайн-бриф. Код по этому документу не пишется, пока каждый блок не будет отдельно обсуждён и взят в работу.

## Цель страницы

Портфолио прикладывается к резюме для hiring manager и руководителей образовательных продуктов. Оно должно быстро показать четыре стороны профиля: преподавание, создание образовательных программ и контента, руководство учебным процессом и живую коммуникацию с людьми.

Главное действие — написать с предложением роли в Telegram. Второе действие — изучить работы и материалы до контакта.

## Визуальная система

Использовать утверждённую систему «практическая рабочая среда»: тёмный Hero и тёмный блок работ, светлые поверхности для остальных разделов, Studio Ink `#17141D` и Signal Blue `#2D63E5` только для действий и keyboard focus. Teal не используется. Руководящую роль не выделять отдельной цветной секцией: она раскрывается в начале блока о создании обучения.

Одна фотография остаётся в Hero. Остальные визуальные доказательства — реальные превью видео, презентаций и документов. До получения оригинальных обложек использовать ясные заглушки, не выдавая их за готовые материалы.

## Порядок блоков

1. **Hero.** Четыре коротких утверждения без подзаголовка: «Преподаю. Записываю видео. Создаю программы. Руковожу техническим обучением». Telegram — главное действие; переход к работам — второе.
2. **Работы и материалы.** Сразу после Hero; без описательного текста и дополнительного подзаголовка. Четыре крупные карточки: RTK Query, фрагмент занятия, React Style Guide и Front-end roadmap. Ниже — компактный линейный перечень «Ещё материалы» с небольшими кликабельными обложками для каждого курса, презентации и видео-кейса. Один материал показывается только в одном месте.
3. **Как я строю обучение.** Начинается с короткого тезиса о руководящей роли: «Руковожу созданием обучения: задаю стандарт программы, материалов, практики и обратной связи для студентов». Далее — последовательность: исследование темы → проектирование программы → создание материалов → проведение обучения → проверка и улучшение. Форматы, домашние задания, экзамены, code review и обратная связь встроены в соответствующие шаги, а не существуют отдельной секцией.
4. **Как я веду занятия.** Личная преподавательская практика: вопросы вместо монолога, реальные сценарии, живая обратная связь и комфортная коммуникация. Пока в блоке используется тот же фрагмент занятия, что и в выбранных работах; после появления нового ролика и обложки он заменяет этот временный материал.
5. **Техническая экспертиза и коммуникация.** Один компактный блок с двумя смысловыми группами: «Что глубоко знаю» (frontend, UI-системы, инженерные практики, AI) и «Как превращаю это в понятный материал» (вебинары, короткие видео, поддержка контента, диалог с аудиторией).
6. **Контакт.** Тёмная секция с Telegram как основным каналом и email как альтернативой.

## Ключевые взаимодействия и состояния

- Выбранные работы: четыре кликабельные карточки с обложкой, кратким описанием и внешней ссылкой. Они остаются первым доказательством после Hero.
- «Ещё материалы»: линейные группы по типам — видеокурсы, презентации и видео-кейсы. У каждой строки есть небольшая кликабельная обложка; карточки выбранных работ здесь не повторяются.
- YouTube: статичная обложка и кнопка воспроизведения; iframe загружается после клика. Всегда есть резервная ссылка на YouTube.
- Презентации, Style Guide и методические материалы: кликабельная обложка, краткое описание и внешняя ссылка. До получения оригинальных ассетов используются подписанные заглушки.
- Внешние ссылки должны иметь понятные подписи, корректные состояния hover/focus и открываться безопасно.
- На мобильных устройствах медиаматериалы идут одной колонкой; интерактивные цели — не менее 44×44 px.

## Контент для Style Guide

**Короткое позиционирование:**

> Документирую инженерные правила так, чтобы ими было удобно пользоваться каждый день: быстро находить нужное, копировать решения, возвращаться к договорённостям и применять их в команде.

**Описание кейса:**

React Style Guide — подробное руководство по чистому, единообразному и масштабируемому коду на React и TypeScript. Оно охватывает нейминг, структуру проекта, импорты, типы, комментарии, pull request, коммиты и рабочее окружение: ESLint, Prettier, Stylelint, aliases, Vite и WebStorm. Отдельное внимание — feature-based архитектуре, читаемости кода и единым командным стандартам.

## Материалы, которые понадобятся перед реализацией соответствующих блоков

- Новое видео и обложка для блока «Как я веду занятия»; до их появления используется текущий фрагмент занятия.
- Ссылки и обложки материалов, которые войдут в линейный перечень «Ещё материалы».

## Рекомендуемый порядок реализации

1. Hero и блок выбранных работ.
2. Единый раздел «Работы и материалы, которые можно проверить».
3. «Как я веду занятия».
4. «Как я строю обучение».
5. «Техническая экспертиза и коммуникация» и контакт.
