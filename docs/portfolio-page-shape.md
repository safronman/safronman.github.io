# Архитектура страницы портфолио

Статус: подтверждённый дизайн-бриф. Код по этому документу не пишется, пока каждый блок не будет отдельно обсуждён и взят в работу.

## Цель страницы

Портфолио прикладывается к резюме для hiring manager и руководителей образовательных продуктов. Оно должно быстро доказать три вещи: техническую глубину, способность строить образовательные программы и качество созданных видео и материалов.

Главное действие — написать с предложением роли в Telegram. Второе действие — изучить работы и материалы до контакта.

## Визуальная система

Использовать утверждённую систему «практическая рабочая среда»: тёмный Hero и motion-кейс, светлые поверхности для проверяемых материалов, Studio Ink `#17141D`, Signal Blue `#2D63E5` для действий, Mineral Teal `#2B6A61` для ссылок, иконок и меток, а Teal Surface `#245950` — для блока о руководящей роли.

Одна фотография остаётся в Hero. Остальные визуальные доказательства — реальные превью видео, презентаций и документов. До получения оригинальных обложек использовать ясные заглушки, не выдавая их за готовые материалы.

## Порядок блоков

1. **Hero.** Роль и ценностное предложение, Telegram CTA, переход к работам.
2. **Руководитель направления.** Управление преподавателями, программами и инженерными стандартами при сохранении близости к учебному процессу.
3. **Как строится обучение.** Исследование темы → программа и практика → материалы и проведение → проверка знаний → улучшение.
4. **Преподавание, которое вовлекает.** Личная преподавательская практика: вопросы вместо монолога, реальные сценарии, живая обратная связь и комфортная коммуникация. Один главный фрагмент занятия или два коротких фрагмента; это не дублирует галерею видеокурсов.
5. **Видео-курсы.** Три кликабельных превью с ленивой загрузкой YouTube по действию пользователя: RTK Query, Git и GitHub, современная разработка компонентов с Portal и Storybook.
6. **Презентации.** Три кликабельные обложки презентаций, показывающие умение объяснять технические концепции визуально.
7. **Motion case: Real-Time.** Отдельный кейс-видео о различиях HTTP, WebSocket, short polling, long polling и SSE. Демонстрирует техническую систематизацию, motion design и HyperFrames.
8. **React Style Guide — методическое пособие.** Один глубокий кликабельный кейс с обложкой и ссылкой на полное руководство.
9. **Форматы и оценка.** Интенсивы, live-уроки и вебинары, домашние задания, экзамены, code review, обратная связь и методические стандарты. Оформить как структурированный перечень, не как сетку одинаковых карточек.
10. **Техническая основа.** Короткий контекст технической экспертизы: frontend, UI-качество, инженерные практики и AI-инструменты. Это не CV-список, а основание доверия к новым обучающим темам.
11. **Технический голос для маркетинга.** Вебинары, короткие видео, ответы клиентам, техническая экспертиза для контента и обратная связь по постам. Блок расширяет профиль, но не должен перебивать образовательную историю.
12. **Контакт.** Telegram как основной канал, email как альтернатива.

## Ключевые взаимодействия и состояния

- YouTube: статичная обложка и кнопка воспроизведения; iframe загружается после клика. Всегда есть резервная ссылка на YouTube.
- Презентации, Style Guide и методические материалы: кликабельная обложка, краткое описание и внешняя ссылка. До получения оригинальных ассетов используются подписанные заглушки.
- Motion-кейс: основное видео, краткая роль автора и ссылка на полный материал.
- Внешние ссылки должны иметь понятные подписи, корректные состояния hover/focus и открываться безопасно.
- На мобильных устройствах медиаматериалы идут одной колонкой; интерактивные цели — не менее 44×44 px.

## Контент для Style Guide

**Короткое позиционирование:**

> Документирую инженерные правила так, чтобы ими было удобно пользоваться каждый день: быстро находить нужное, копировать решения, возвращаться к договорённостям и применять их в команде.

**Описание кейса:**

React Style Guide — подробное руководство по чистому, единообразному и масштабируемому коду на React и TypeScript. Оно охватывает нейминг, структуру проекта, импорты, типы, комментарии, pull request, коммиты и рабочее окружение: ESLint, Prettier, Stylelint, aliases, Vite и WebStorm. Отдельное внимание — feature-based архитектуре, читаемости кода и единым командным стандартам.

## Материалы, которые понадобятся перед реализацией соответствующих блоков

- Ссылки на три выбранных видео и, при возможности, их превью или названия.
- 1–2 фрагмента занятия для блока о преподавании.
- Ссылки и обложки трёх презентаций.
- Видео/ссылка, описание роли и разрешённая публичная формулировка для кейса Real-Time / HyperFrames.
- Ссылка и обложка React Style Guide.
- Примеры или ссылки для маркетингового блока, если они будут публичными.
